# tt-web login security audit

Audited on October 9, 2026 against `origin/main` at `298c23d`, including the pinned `tt-services` dependency. The patch is local on `codex/tt-web-login-audit`; it has not been deployed. No production credentials, database records, or logs were inspected. Findings describe code behavior and isolated reproductions, not evidence of an intrusion.

## Findings and patches

| Severity          | Finding and precondition                                                                                                                                                                                                                                                                                                                             | Patch                                                                                                                                                                                                                                                             |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High              | Concurrent Google operations share one mutable OAuth client. An attacker callback overlapping an admin request can receive the admin's identity and issue an admin-authorized session. The original service was reproduced locally returning the admin email for both concurrent users.                                                              | Give each authorized operation its own client. Authorize the verified email and OAuth audience from the original exchange before storing credentials. Do not re-fetch identity through shared credentials. Reject old sessions with mismatched user ID and email. |
| High              | The dependency logs complete access and refresh tokens; the callback also logs authorization codes. Anyone able to read those logs may obtain Google Drive/Documents credentials.                                                                                                                                                                    | Remove token/code logging and sanitize provider exceptions throughout the patched Google service and login routes.                                                                                                                                                |
| High, conditional | Preview OAuth state is caller-controlled and not browser-bound. The callback sends a reusable production session ID in a redirect URL to any accepted team preview hostname, including HTTP URLs. The bridge also skips signature validation when its secret is absent. A compromised matching preview or access to URL logs can expose the session. | Retire the bridge with HTTP 410 and disable preview login. Production sessions are issued only in HttpOnly cookies. No session ID appears in redirect URLs.                                                                                                       |
| Medium            | OAuth callbacks accept codes without matching an initiating browser or enforcing a transaction deadline. The admin allowlist limits classic login-CSRF scenarios, but it does not provide browser binding.                                                                                                                                           | Add a fresh five-minute state cookie, exact state comparison, S256 PKCE, and cookie cleanup on success/error. Restrict login to the production origins and explicit local development.                                                                            |
| High, conditional | `AUTH_DISABLED=true` bypasses production authorization; development also bypasses by default. Missing `ADMIN_EMAIL` lets `requireAuth()` accept any existing session, while `getIsLoggedIn()` can return true for an anonymous request because both emails are undefined.                                                                            | Require explicit development opt-in outside Vercel. Missing administrator configuration denies access outside the explicitly enabled development bypass.                                                                                                          |
| Medium            | Google Docs actions accept an existing non-admin session, including one whose account was removed from the administrator configuration. Blog revalidation only checks the page render, not the callable action.                                                                                                                                      | Authenticate inside each action and require the configured admin identity for Google user lookup.                                                                                                                                                                 |
| Medium            | Public blog metadata reads do not check publication, exposing private note titles/tags if the note ID is known. Published-but-deleted notes also remain publicly accessible.                                                                                                                                                                         | Require `published === true` and not deleted for list, metadata, and content responses.                                                                                                                                                                           |

The Next.js runtime and its analyzer/ESLint packages were also updated from 15.5.18 to 15.5.27, the current 15.5 security release identified in the [September security announcement](https://nextjs.org/blog/september-2026-security-release). This audit did not establish exploitability of every framework advisory in this application.

## Validation

- The Google identity race was reproduced with the original installed service and fake OAuth/database implementations.
- The regression suite exercises the actual route handlers, auth helpers, and patched service. It covers concurrent identities, invalid sessions/configuration, wrong/missing/expired OAuth state, PKCE forwarding, unauthorized token persistence, verified-email representations, audience validation, error redaction, retired preview login, private action entry points, and unpublished/deleted blog data.
- A fresh installation of `tt-services` using `bun install --frozen-lockfile --ignore-scripts` applies the committed patch; the authentication suite then passes (20 tests, 176 assertions).
- Type checking and lint pass; 58 existing editor unit tests pass.
- A credential-free `next build` compiled successfully and passed its type/lint stages. Static page generation then raised `MONGODB_URI is not defined` while rendering the projects page and remained pending; the build was stopped. A complete production build and live OAuth round trip remain unverified.

The OAuth design follows Google's [web-server OAuth guidance](https://developers.google.com/identity/protocols/oauth2/web-server). Tests use synthetic identities and mocked providers; they do not establish live Google consent, production configuration, or deployment behavior.

## Release and operational follow-up

1. Deploy only after reviewing these changes. Preview login intentionally stops working; production login remains on `https://www.tylertracy.com` and `https://tylertracy.com`. Local authentication now defaults to enabled. Existing legitimate sessions remain valid; legacy mixed-identity sessions are rejected.
2. Assess access to historical application logs without copying credentials into tickets or chat. Because refresh tokens were logged, revoke the affected Google authorization and reconnect after the corrected release if log exposure cannot be ruled out. Deleting logs alone does not revoke tokens. No revocation or log deletion was performed in this audit.
3. Verify production `ADMIN_EMAIL`, Google callback registration, cookie flags, successful admin login/logout, and rejection of another account. Check whether preview deployments receive production MongoDB/Google secrets; disabling the bridge does not isolate preview workloads that already possess those secrets.
4. Upstream the Google service patch and then replace the patched Git dependency with a reviewed fixed revision. Until then, install with Bun and keep the committed patch and lockfile together. Its key uses Bun's resolved short Git revision; a stale key can be silently ignored. The automatic dependency updater is paused because it advances the revision without preserving/testing this patch.

The existing session design uses 36 random bytes, hashes session IDs in MongoDB, rejects expired records, and deletes the record on logout. Middleware's cookie-presence check is only a navigation convenience: panel rendering and callable private actions also perform server-side session authorization. These were not treated as vulnerabilities.

Remaining design tradeoffs include 30-day sessions, Google Drive/Documents scopes coupled to login, and logout triggered by visiting the logout page. This work does not constitute a full review of the external API service, Google document content processing, all transitive dependencies, or infrastructure access controls.
